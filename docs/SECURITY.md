# ضوابط أمن المعلومات — تُجّار ماركت

وثيقة مرجعية لضوابط الأمان المطبّقة فعلياً في الكود، تُستخدم ضمن ملف التقديم للاختبار الفني لدى الهيئة الناظمة
للاتصالات والبريد. كل بند يشير إلى مكان تطبيقه.

الحالة: ✅ مطبّق ومختبر · 🟡 مطبّق ويحتاج إعداد الإنتاج · ⏳ مخطط

---

## 1. المعمارية

- واجهة الزبائن وبوابة التجار ولوحة الإدارة تتواصل مع API واحد (NestJS)، ولكل واجهة جلسة مستقلة
- قاعدة البيانات PostgreSQL ومخزن الصور (MinIO / S3) غير مكشوفين مباشرة للمستخدم
- كل عمليات الكتابة تمر عبر API مع تحقق من الهوية والصلاحية والمدخلات

## 8. المكتبات

| الضابط | الحالة |
|---|---|
| الواجهة: Next.js 16.3.5، و`npm audit` بلا أي ثغرة (إنتاج وتطوير) | ✅ |
| الـ API: NestJS 11.2.5 وPrisma 6.19.3، وأُغلقت كل الثغرات الحرجة والمتوسطة | ✅ |
| الـ API: 6 ثغرات عالية الخطورة لا تُحل إلا بترقية كبرى (NestJS 12 وmulter وأداة إعداد Prisma) | 🟡 مخففة ومجدولة |
| فحص تلقائي للمكتبات في GitHub Actions | ⏳ |

**تخفيف الثغرات المتبقية حتى الترقية:**
- **multer** (رفض خدمة بنماذج رفع مصاغة خبيثاً): حدود صارمة على الرفع (ملف واحد، 3 أجزاء، أسماء حقول قصيرة)، والرفع للتجار المسجلين فقط مع حد للمعدل. انظر `media.controller.ts`.
- **deepmerge-ts عبر @prisma/config:** تُستخدم في أداة Prisma أثناء الإعداد والترحيل فقط، ولا تعالج أي بيانات من المستخدمين.
- **الترقية إلى NestJS 12:** مهمة مستقلة مع اختبار شامل، ويجب إنجازها قبل التقديم للهيئة.
