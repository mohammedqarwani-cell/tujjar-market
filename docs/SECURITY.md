# ضوابط أمن المعلومات — تُجّار ماركت

وثيقة مرجعية لضوابط الأمان المطبّقة فعلياً في الكود، تُستخدم ضمن ملف التقديم للاختبار الفني لدى الهيئة الناظمة
للاتصالات والبريد. كل بند يشير إلى مكان تطبيقه.

الحالة: ✅ مطبّق ومختبر · 🟡 مطبّق ويحتاج إعداد الإنتاج · ⏳ مخطط

---

## 1. المعمارية

- واجهة الزبائن وبوابة التجار ولوحة الإدارة تتواصل مع API واحد (NestJS)، ولكل واجهة جلسة مستقلة
- الواجهات الثلاث تطبيقات منفصلة: كل بناء لا يحتوي إلا صفحاته والصفحات المشتركة (الشروط، الخصوصية)،
  فكود لوحة الإدارة لا يُرسل أبداً إلى متصفح الزبون أو التاجر (`apps/web/next.config.ts`، `pageExtensions`)
- قاعدة البيانات PostgreSQL ومخزن الصور (MinIO / S3) غير مكشوفين مباشرة للمستخدم
- كل عمليات الكتابة تمر عبر API مع تحقق من الهوية والصلاحية والمدخلات

## 8. المكتبات

| الضابط | الحالة |
|---|---|
| الواجهة: Next.js 16.3.5، و`npm audit` بلا أي ثغرة (إنتاج وتطوير) | ✅ |
| الـ API: NestJS 12.0.3 (multer 2.4.0، Express 5.2.1) وPrisma 6.19.3، و`npm audit` بلا أي ثغرة (إنتاج وتطوير) | ✅ |
| `deepmerge-ts` مثبّتة على 8.0.2 عبر `overrides` في `package.json` لإغلاق ثغرة أداة إعداد Prisma | ✅ |
| فحص تلقائي للمكتبات في GitHub Actions | ⏳ |

**ملاحظات الترقية إلى NestJS 12:**
- المشروع يبقى CommonJS ويحمّل حزم Nest (ESM فقط) عبر `require(esm)`، ويتطلب Node.js 22.12 أو أحدث.
- `@nestjs/throttler` لا يدعم NestJS 12 بعد، فاستُبدل بحارس داخلي مكافئ ومختبر (`common/throttle.ts`).
- أداة `@nestjs/cli` بقيت على الإصدار 11 للبناء، لأن إصدارها 12 يتطلب TypeScript 6 وNode.js 22.22.3 أو أحدث.
- أُعيد تعريف `@Optional()` في `JwtAuthGuard`، لأن NestJS 12 لم يعد يورّثه من الفئة الأم.
